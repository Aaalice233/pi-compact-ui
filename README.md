# Compact UI

Pi 的中文紧凑界面：把连续的思考和工具调用收进一个可展开的工作组，让正文成为阅读重点。

这是 `pi-compact-ui` 0.1.3 的个人 fork。上游未声明许可证，本仓库保持私有，仅供个人使用。

## 展示方式

已完成的组收起时只占一行（组与正文之间的间隔不计入），保留工具分类次数、编辑增减与失败数量：

```text
 ▸ bash×2 edit×3 read×1 · +19 −43 · 失败1
```

本块还没被本轮回复或运行结束封存时，组逐行展开显示全部调用（含已完成的）；调用结束**不会**把行收起来，避免“展开一下又收起”的闪动。直到本轮正式回复或运行结束，块被封存后才折回单行。收起状态不显示思考原文，纯思考组也只保留标题。

每个调用行的右侧是一列对齐的「结果摘要 + 耗时」：edit 的增减、read 的行范围、搜索计数、退出码与耗时共用这一列，同一组内各自右对齐；该列紧跟本组最宽的一行，不随终端变宽滑到屏幕最右。窄终端先舍弃右列，保住工具与错误正文。

一级展开只显示完整工具清单，每个调用一行，不插入返回正文或代码块：

```text
 ▾ read×1 bash×1 edit×1 grep×1 · +11 −8 · 失败1
 │  ✓ read  src/用户/认证.ts                12–40 行 0.1s
 │  ✗ bash  npm test · 断言失败：会话未过期          3.2s
 │  ✓ edit  src/配置/解析.ts                  +11 −8 0.4s
 ╰  ✓ grep  toolElapsed in index.ts             5 项 0.3s
```

暂不提供二级展开。需要某个工具的原生完整展示时，可将其加入 `nativeTools`。

- 成功历史弱化显示，运行中用主题强调色；失败有 `✗` 和中文数量，不仅依赖红色。标题里的 `失败N` 用主题灰色（`muted`），只作事实陈述，红色留给展开后的 `✗` 与错误正文。
- 标题只保留工具分类汇总，例如 `bash×1 edit×2 read×1`；运行中的调用由下面的进度行交代，不再重复计数，也不再显示思考 token。工具之间只留空格，`·` 用于分隔工具清单、增减与失败数量。收起时失败只保留数量，展开后才显示简短错误。
- 工具名按列对齐；右列先放结果摘要再放耗时，两者都右对齐，运行中的耗时持续更新、已完成的定格为最终值，不足 0.1s 的调用不显示耗时。这一列紧跟本组最宽的一行，而不是屏幕最右侧；窄终端优先保留工具/错误内容，先隐去右列。
- 思考原文默认隐藏。展开后，有工具的组保留一行思考摘要，纯思考组显示受行数限制的多行思考。预览使用主题思考色和斜体，平铺工具行避免多级树枝交错。运行中自动展开只列调用行，不会每帧重解析流式思考的 Markdown。
- **fullscreen 模式可单击组标题文字**，只展开/收起当前组（纯思考组也支持）；正文拖选、滚轮和输入框焦点不受影响，标题右侧空白不触发切换。
- `Ctrl+O` 仍用于统一展开/折叠，包括本轮正在展开的块：手动收起后这个块不再自动展开，本轮回复把它封存后，新块恢复自动展开。普通滚动终端模式不接收这套鼠标事件，请用键盘。标题、设置、压缩摘要和用时提示使用中文。
- 实际结果提供信息时，右列显示 edit 的 diff 行数、read 的行范围、搜索计数或退出码，紧接着就是耗时。增减分别使用主题的 `toolDiffAdded`（绿）和 `toolDiffRemoved`（红），例如 `+1 −2 0.3s`。未知格式不猜数值，失败结果不标成功增减量、错误正文留在行内。调用摘要（命令、路径、搜索词）只受行宽限制，不再用固定字符数提前截断。历史工具没有原始计时，毫秒级调用也不显示 `0.0s`，两者都不占右列宽度。
- 折叠标题同样显示绿色新增、红色删除，如 `edit×3 · +19 −43`：仅累计这一组实际返回的成功编辑 diff，失败、进行中或未提供 diff 的调用不计入；没有数据时不伪造 `+0 −0`。这是调用累计量，不是 Git 工作区净差异。
- 回合结束使用短提示 `── 用时 42s`，不再用满宽横线抢占视觉重点。
- Markdown 代码块保持主题背景、语法高亮和独立语言标签；不把语言塞进代码正文，以免影响复制阅读。

## 不改变执行语义

只改 TUI 展示，不改模型消息、工具执行、工具定义或会话文件。非 TUI 模式不装组件补丁，也不参与共享 UI 状态的事件处理。工具的原生说明、promptGuidelines、shellPath 等不会被覆盖。

以下工具默认保留自带渲染器，并切分前后的折叠组：

```json
[
  "plan_mode_complete",
  "subagent",
  "propose_goal_draft",
  "create_goal",
  "set_goal_tasks",
  "update_goal"
]
```

因此计划正文、子代理实时进度和目标确认内容仍可直接查看。

## 安装与设置

```sh
pi install git:github.com/Aaalice233/pi-compact-ui
```

安装/更新后执行 `/reload`。输入 `/compact-ui-config` 打开中文设置：方向键选择、Enter 调整、Esc 返回；数值调整支持左右键和 `−/+`。

配置文件：`~/.pi/agent/compact-ui.json`，遵循 `PI_CODING_AGENT_DIR`。

```json
{
  "expandedThinkingLines": 10,
  "nativeTools": [
    "plan_mode_complete", "subagent", "propose_goal_draft",
    "create_goal", "set_goal_tasks", "update_goal"
  ]
}
```

| 选项 | 默认值 | 范围/作用 |
|---|---|---|
| `expandedThinkingLines` | 10 | 1–100，纯思考组展开后的预览 |
| `nativeTools` | 上述名单 | 原生显示的工具名，支持 `*` 通配符 |

旧配置中的 `collapsedMaxLines`、`expandedToolLines` 已不使用，可删除；已完成组收起为单行，工具组展开始终是完整清单。

首次 TUI 启动创建默认配置；保存文件自动生效，无需 `/reload`。数值规整为范围内整数。`nativeTools` 整体替换默认名单，只影响之后创建的工具，既有组不会重建。

## 历史和生命周期

恢复会话、切换分支、压缩后保留消息及 `/reload` 时，从仍存在的助手消息恢复思考块，按正文边界保持顺序。纯思考和工具调用前的思考也有展开入口。

- `Ctrl+O` 对工具组显示完整调用清单；纯思考组显示受行数限制的思考预览，不是无限全文。
- 供应商未返回的思考、加密思考和已移出当前分支的原文无法恢复。
- 实时终帧不会重复生成历史组；主题、宽度变化和重复重建保留各组单独点击的展开状态，`Ctrl+O` 可统一覆盖。
- 已完成的历史组复用渲染缓存，不启动转圈。未完成工具在回合结束标记为中断，停止动画。
- 同进程 SDK 子会话即使共享模块或事件处理器，其 `print` / `json` / `rpc` 事件也不会改写主 TUI 的思考、计时、工具状态、动画或原型补丁。RPC 的 `hasUI` 不代表它拥有终端界面。
- 仅已启动且尚未关闭的 TUI 实例处理对应模式的 UI 事件；旧实例的迟到事件不会中断新界面的工具。这里支持一个主 TUI 加无界面子会话，不承诺同进程多个独立 TUI 的并行隔离。
- `/reload` 窗口保留补丁，直到新实例接管；其他关闭恢复原型，并清理动画和配置监听的定时器。

## 性能与验证

静态组按内容/宽度缓存；助手 Markdown 规范化复用原始行数组缓存；组失效不级联重跑隐藏工具的渲染器。一级展开不解析工具返回正文的 Markdown；纯思考预览先限长再拆行/高亮。主会话和外部组共用标题/工具行排版。

```sh
npm ci
npm run check
npm test
npm run bench
npm run bench -- --thinking
npm run bench -- --expanded
npm run preview
```

测试使用真实 Pi 组件，覆盖分组、分类计数、原生工具边界、流式/历史思考、重载、缓存、错误提示、中文宽度、极窄屏和主题失效；通过 fullscreen 原生 SGR 按下/松开事件验证标题点击、输入焦点，以及 Container 的嵌套组事件路由；同进程隔离测试覆盖共享模块/处理器、子会话结束、同名工具 ID、思考流和动画生命周期。`preview` 输出宽屏与窄屏的真实组件渲染；终端字体、配色以及完整交互手感仍需在你自己的终端确认。

基准是合成对话树的稳态渲染，不代表完整终端的滚动或首次高亮成本；不要把不同机器/负载下的绝对数字直接比较。
