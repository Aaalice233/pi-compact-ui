# Compact UI

Pi 的中文紧凑界面：把连续的思考和工具调用收进一个可展开的工作组，让正文成为阅读重点。

这是 `pi-compact-ui` 0.1.3 的个人 fork。上游未声明许可证，本仓库保持私有，仅供个人使用。

## 展示方式

折叠态默认不超过三行（组与正文之间的间隔不计入）：

```text
 ▸ 3 个工具 · 1 失败 · 思考 1.2K
 │  ✗ bash  npm test · 断言失败：会话未过期 · 3.2s
 ╰  验证过期会话分支；失败项需要重新检查。
```

- 成功历史弱化显示，运行中用主题强调色；失败有 `✗` 和中文数量，不仅依赖红色。
- 默认优先保留失败项、运行中的工具，再显示最近的成功项。标题始终显示全部工具数。
- 工具名按列对齐，耗时紧跟工具摘要，思考 token 紧跟标题；不按终端宽度把关联信息推到最右侧。窄终端优先保留工具/错误内容，先隐藏辅助信息。
- 思考预览使用主题思考色和斜体。展开箭头与圆角末级引导线保持轻量，不加大块边框。
- `Ctrl+O` 展开全部工具与结果预览，再按一次折叠；标题、设置、压缩摘要和用时提示使用中文。
- 实际结果提供信息时，显示 edit 的 diff 行数、read 的行范围、搜索计数或退出码。未知格式不猜数值。历史工具没有原始计时，不伪造 `0.0s`。
- 回合结束使用短提示 `── 用时 42s`，不再用满宽横线抢占视觉重点。
- Markdown 代码块保持主题背景、语法高亮和独立语言标签；不把语言塞进代码正文，以免影响复制阅读。

## 不改变执行语义

只改 TUI 展示，不改模型消息、工具执行、工具定义或会话文件。非 TUI 模式不装组件补丁。工具的原生说明、promptGuidelines、shellPath 等不会被覆盖。

以下工具默认保留自带渲染器，并切分前后的折叠组：

```json
[
  "plan_mode_complete",
  "subagent",
  "propose_goal_draft",
  "create_goal",
  "set_goal_tasks",
  "update_goal"
]
```

因此计划正文、子代理实时进度和目标确认内容仍可直接查看。

## 安装与设置

```sh
pi install git:github.com/Aaalice233/pi-compact-ui
```

安装/更新后执行 `/reload`。输入 `/compact-ui-config` 打开中文设置：方向键选择、Enter 调整、Esc 返回；数值调整支持左右键和 `−/+`。

配置文件：`~/.pi/agent/compact-ui.json`，遵循 `PI_CODING_AGENT_DIR`。

```json
{
  "collapsedMaxLines": 3,
  "expandedToolLines": 5,
  "expandedThinkingLines": 10,
  "nativeTools": [
    "plan_mode_complete", "subagent", "propose_goal_draft",
    "create_goal", "set_goal_tasks", "update_goal"
  ]
}
```

| 选项 | 默认值 | 范围/作用 |
|---|---|---|
| `collapsedMaxLines` | 3 | 2–20，含标题与思考预览；两行模式优先显示工具 |
| `expandedToolLines` | 5 | 1–50，每个工具的结果预览 |
| `expandedThinkingLines` | 10 | 1–100，展开的思考预览 |
| `nativeTools` | 上述名单 | 原生显示的工具名，支持 `*` 通配符 |

首次 TUI 启动创建默认配置；保存文件自动生效，无需 `/reload`。数值规整为范围内整数。`nativeTools` 整体替换默认名单，只影响之后创建的工具，既有组不会重建。

## 历史和生命周期

恢复会话、切换分支、压缩后保留消息及 `/reload` 时，从仍存在的助手消息恢复思考块，按正文边界保持顺序。纯思考和工具调用前的思考也有展开入口。

- `Ctrl+O` 显示的是受行数限制的预览，不是无限全文。
- 供应商未返回的思考、加密思考和已移出当前分支的原文无法恢复。
- 实时终帧不会重复生成历史组；主题、宽度变化和重复重建保留展开行为。
- 已完成的历史组复用渲染缓存，不启动转圈。未完成工具在回合结束标记为中断，停止动画。
- `/reload` 窗口保留补丁，直到新实例接管；其他关闭恢复原型，并清理动画和配置监听的定时器。

## 性能与验证

静态组按内容/宽度缓存；助手 Markdown 规范化复用原始行数组缓存；组失效不级联重跑隐藏工具的渲染器。预览先限长再拆行/高亮，不为几行预览拆分数 MB 输出。主会话和外部组共用标题/工具行排版。

```sh
npm ci
npm run check
npm test
npm run bench
npm run bench -- --thinking
npm run preview
```

测试使用真实 Pi 组件，覆盖分组、原生工具边界、流式/历史思考、重载、缓存、错误提示、中文宽度、极窄屏和主题失效。`preview` 输出宽屏与窄屏的真实组件渲染；终端字体、配色以及完整交互手感仍需在你自己的终端确认。

基准是合成对话树的稳态渲染，不代表完整终端的滚动或首次高亮成本；不要把不同机器/负载下的绝对数字直接比较。
